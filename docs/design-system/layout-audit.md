# AI Lab 布局审核与建议

版本3.0.0 · 2026-10-21。V3 是设计评审稿；本轮未改变生产业务页面。

## 评估口径

严重等级描述问题对用户的影响，不表示视觉改动有多大，也不表示业务功能被验证有缺陷。

- **P0 / 阻断**：无法完成关键任务、关键内容不可达、焦点丢失等有证据的阻断。当前布局审核未发现可直接定为P0的问题。
- **P1 / 显著影响**：结构变化增加学习成本、主次冲突导致理解或操作困难、窄窗口内容不可达；建议下一次组件迁移处理。
- **P2 / 改进**：密度、留白、视觉一致性与美感优化；不影响任务完成，可在常规迁移收敛。

改动规模另列：无结构改动 / 局部微调 / 条件布局变化 / 信息架构变化。没有使用测试或用户研究时，不把审美偏好写成可量化效率提升。

## 视觉整改优先级

| 建议                                      | 等级 | 原因                                 | 风险与验收                                   |
| ----------------------------------------- | ---- | ------------------------------------ | -------------------------------------------- |
| 中性表面取代大面积紫色背景                | P1   | 让数据、选择和动作彼此可辨           | 检查浅/深主题、叠层文字与图表对比            |
| 控件8px、卡12px、弹窗16px；36/32/48px密度 | P2   | 形成明确尺度，延续用户已选择8px控件  | 所有调用点回归，按钮不能挤压文案             |
| 正文14/22/400，辅助12/18/400              | P1   | 避免标签字重继承到输入、标题抢占内容 | 中文长文、200%缩放与弱视可读性检查           |
| 单源令牌、共享组件统一消费                | P1   | 防止局部CSS覆盖再次造成漂移          | 生成检查通过只是文档一致性；真实组件仍需迁移 |
| 细边界、静态轻阴影、不做卡片抬起          | P2   | 减少视觉噪声和不必要位移             | 检查交互可发现性与键盘焦点                   |

## 采用顺序

先建立主题与共享基础控件映射，再迁移容器与导航，最后按模块逐个替换；每个阶段比较相同窗口尺寸、主题与示例数据。任何改变模块顺序、列宽比例、侧栏宽度、页面主操作位置的提案，必须单独记录问题、等级、改动规模及截图依据，不能夹带在视觉统一中。
