# MyDashboard 设计规范 2.0 · HeroUI edition

版本：**2.0.0（用户修订）** · 生效日期：**2026-10-22** · 状态：**设计与后续开发基线，生产迁移待实施**。

适用对象：设计师、开发者、代码代理与评审者。适用范围：Electron renderer 的全部新页面、组件、业务弹层、主题、图标、排版和交互变更。“必须 / 禁止”为交付门槛，“建议”为可评审取舍的指导。

## 1. 权威与版本

优先级：用户最新明确决策 → 本规范与页面规格 → HeroUI **3.2.6** 发布包默认主题、公开 API 与同版本样例 → 采纳提案技术依据 → 历史资料。提案的页面结构约束已在本版承接，冲突时以本版为准。

用户要求的“2.0”是本次设计合同版本，替代历史自建 v1 / v3.2；提案“UI v4”工作名统一收敛到本版。HeroUI v3、React 19 与规范 2.0 是不同维度。

必须固定 `@heroui/react@3.2.6` 与 `@heroui/styles@3.2.6`。独立设计稿使用 React 19 / Tailwind 4，生产仍为 React 18 / Tailwind 3；正式迁移前必须通过依赖、构建和 Electron 兼容试点。禁止绕过 peer、混装 HeroUI v2/v3 或在生产窗口长期加载两套 Tailwind。

## 2. 体验与维护边界

MyDashboard 是本地优先的 macOS 创作与效率工作台。用户要理解今天的工作、继续创作、管理素材并观察 AI 账户状态。内容、当前任务与进度优先。

| 层       | 维护责任                                                   | 必须遵守                                                     |
| -------- | ---------------------------------------------------------- | ------------------------------------------------------------ |
| 上游组件 | HeroUI 3.2.6                                               | 圆角、控件字号、尺寸、阴影、内距、动效、焦点、键盘和公开变体 |
| 项目适配 | 现有项目配色、主题状态、用户主色桥、中文系统字体、品牌资产 | 单一入口、沿用现有主题，适配可追溯                           |
| 业务组合 | 网格、导航、Radar、订阅、编辑器、媒体和任务                | 基础组件组合；保留业务引擎、数据契约与模块顺序               |

Button、Select、Checkbox、Radio、Switch、Slider、Calendar、Modal 等必须使用真实 HeroUI。仅对已多处调用的稳定业务入口保留窄兼容层；新代码优先用原生 Props，不为每个上游组件建立转发层。

## 3. 基础视觉

### 3.1 颜色与主题

**必须沿用当前项目主题**：紫色主色、黄色辅助色，以及现有浅深色背景、内容层级和文字色。颜色来源为生产 `src/renderer/styles/globals.css`；默认主色和深浅色主色计算以 `src/renderer/stores/settingsStore.ts` 为准。主要动作使用 `primary` 公开变体；Logo 与第三方品牌图形保留固有色。

设计稿唯一主题适配入口为 `v2/project-theme.mjs`：构建时读取上述源码，映射到 HeroUI 官方 CSS 变量，不复制一套独立色板。当前默认浅色主色为 `rgb(107 56 212)`，深色按设置逻辑计算为 `rgb(196 175 238)`；深色 CSS 中静态 `208 188 255` 会被运行时设置覆盖，不能当成最终主色。页面背景分别为 `rgb(249 249 255)` / `rgb(21 28 39)`。这些数值是来源说明，不是另建 token。

| 用途        | 上游语义角色                                                               | 规则                                                                      |
| ----------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| 页面 / 内容 | `--background` / `--foreground`                                            | 完整 CSS 颜色，不能再次包 `rgb(...)`                                      |
| 卡片 / 浮层 | `--surface` / `--surface-foreground`、`--overlay` / `--overlay-foreground` | 库组件默认层级                                                            |
| 辅助文案    | `--muted`                                                                  | 检查实际对比度                                                            |
| 主要动作    | `--accent` / `--accent-foreground`                                         | 映射现有 primary / on-primary，保留成对前景色                             |
| 状态        | `--success`、`--warning`、`--danger` 与对应 foreground                     | 警示沿用项目黄色、错误沿用项目 error；现有主题无 success 时沿用上游语义绿 |
| 边界        | `--border` / `--separator`                                                 | 业务区块可引用，不重画控件边界                                            |
| 表单 / 焦点 | `--field-*` / `--focus`                                                    | 交给库，不逐页重画焦点环                                                  |

主题类必须位于 `document.documentElement`，保证 portal 一起切换。生产保留 light / dark / system 与已保存的显式用户主色。主色经一个主题桥写入官方变量及配对前景色；旧 RGB 变量隔离为 `--md-legacy-*`，旧 utility 使用 `legacy-*`。自定义色检查文字 4.5:1、交互图形与焦点 3:1；**用户已确认：不足时明确提示，但允许保存**，不静默改用户颜色、不强制拦截。默认主题仍需达标。设计稿不读写生产设置，不表示生产用户主色桥已完成。

### 3.2 字体、形状、尺寸和动效

基础控件沿用上游 Typography、Label、Description、Card.Title、Modal.Heading 角色。业务排版优先沿用现有项目：中文 Noto Sans SC、英文 Plus Jakarta Sans，并补系统字体回退；不依赖运行时 Google Fonts。桌面业务内容以紧凑为目标，优先复用已有 4/8/12/16/24px 内容间距；不要增加大面积装饰性留白或新增营销式页头。大标题、全局 padding、分栏属于布局调整，须有审核证据并确认后采用。

**禁止复制旧 8px 控件 / 12px 卡片 / 16px 弹窗、13px 按钮字体、统一 36px 控件规则。** HeroUI 的不同组件有不同默认形状。基础 `--radius` 为 8px 不代表 Button 为 8px；默认桌面 md Button 约 36px 高 / 24px 半径只是同版本观测值，不是项目 token。

尺寸与外观使用公开 `size` / `variant`；常规表单 md，密集列表操作、筛选和工具栏优先 sm，以具体组件实际 API 为准。禁止覆写基础组件 height、padding、border-radius、font-size、box-shadow 或 transition 建立私有密度。Card / Modal / Drawer 的内距与外壳保持默认；业务内部网格由内容容器负责。紧凑不得通过缩小可点击范围、隐藏标签或裁剪错误信息实现。

动效沿用上游并尊重 `prefers-reduced-motion`。静态卡片不额外抬起或缩放。进度来自真实任务；未知值用 indeterminate / Spinner，不伪造百分比。

### 3.3 图标与品牌

保留 `assets/app-logo.svg` 与品牌资产。**优先使用 `@heroui/react@3.2.6` 公开导出的自带图标**（已核实 15 个基础图标），控件箭头、勾选、关闭直接沿用组件内置图形。HeroUI 不附带完整业务图标库；用户已确认，缺少的业务图标使用 **`@heroicons/react@2.2.0` 的 `24/outline`** 补充，统一在 `v2/src/icons.tsx` 映射。Heroicons 是独立 MIT 图标库，生产迁移保留随包许可证。

新增设计不继续使用 Material Symbols，不引入第三套通用图标库、不手绘替代已有图标。常规图标 20px，继承文字颜色；纯图标动作必须有可访问名称；可操作时提供 Tooltip，禁用时就近说明原因。长标签可用可访问描述补全。品牌图形使用对应明暗变体。生产原图标属于待迁移存量，按页替换。

## 4. 页面布局

项目只维护布局 token，源为 [`v2/layout.json`](v2/layout.json)，前缀 `--md-layout-*`。不另建上游颜色、字体、形状 JSON 副本。

| 布局项    | 规则                                                                         |
| --------- | ---------------------------------------------------------------------------- |
| 桌面导航  | 280px，保留模块顺序和设置入口；品牌区避开 macOS 交通灯                       |
| 顶栏      | 沿用现有左侧搜索、右侧通知 / 用户入口；约 56px，交互区 no-drag，不新增面包屑 |
| 内容      | 沿用页面 padding 48px；已有 max-width 1280px 的页面保留，Dashboard 保持全宽  |
| 模块      | gap 24px；Dashboard 保留 48px 分栏间距与 320px 右栏                          |
| AI Lab    | 无额外大页头；Radar / Usage 5:7 → 横向订阅 → 工具目录                        |
| Video     | 页头 → 封面 → 音频 / 演示文稿；保留 Voiceover 弹窗入口                       |
| Voiceover | max 1040px / 720px 工作区，304px 任务栏；固定标题、主操作和试听区            |

保留生产断点：侧栏 md / 768px 显示；AI Lab 首行和 Dashboard 在 lg / 1024px 开始双栏，AI 工具目录为 2 / md:3 / lg:4 列，Video 音频 / 演示为 lg:1:2。1024px 仍为桌面布局，不沿用上一稿擅自增加的 1280px 单列断点。订阅局部横滚。Dashboard 保留两栏独立滚动；统计区保留双额度 → 7 日图 → 5 项指标的垂直顺序。

窄窗口和 200% 缩放保证动作可达；已有断点下若发生遮挡，先记录受影响宽高、截图、内容和备选方式，再请用户确认布局调整，不以“响应式优化”自行改产品结构。不新增移动导航、FAB 或手机信息架构。侧栏保留 New Project、设置和用户入口。

布局 token 不控制基础组件内部。改变模块顺序、比例、侧栏宽、断点或主动作位置，必须另附问题证据、影响、备选布局和前后截图，**经用户确认后**同步本规范。保留现有布局是默认决策。

**保留布局必须落实到每个 item 内部**：沿用生产组件的图标 / 品牌、标题 / 服务商、描述、费用 / 日期、分类 / 状态的顺序与同行关系，以及宽度、对齐、业务字号、内容间距、操作位置和显隐方式。替换为 HeroUI 不构成重新排列内容的许可。先核对对应生产组件，再使用库默认外壳承载原有业务组织；具体 item 合同见页面规格。item 排版变更同样须提供审核证据并经用户确认。

## 5. 组件合同

| 场景     | 组件 / 公开方式                                                             | 验收                                         |
| -------- | --------------------------------------------------------------------------- | -------------------------------------------- |
| 主次动作 | Button primary / secondary / tertiary / ghost；危险动作采用上游 danger 变体 | 同一区域最多一个主要动作                     |
| 导航链接 | Link + React Router 适配，应用导航为业务组合                                | 不整页刷新，`aria-current` 标注选中          |
| 字段     | TextField + Label + Input/TextArea + Description/FieldError                 | 标签常驻，错误就近，placeholder 仅作示例     |
| 单选多选 | RadioGroup / CheckboxGroup                                                  | 表单模式用 RadioGroup；区分 0、空值和未选择  |
| 下拉     | Select / ComboBox + ListBox                                                 | v3 compound API，支持键盘、中文和空列表      |
| 内容导航 | Tabs                                                                        | 用于平级内容，不替代配音方式单选             |
| 开关数值 | Switch / Slider / NumberField                                               | label、当前值、键盘、禁用说明齐全            |
| 日期颜色 | DatePicker / Calendar、ColorPicker 家族                                     | locale 正确，日期值与 UTC 时间明确转换       |
| 容器     | Card / Surface                                                              | 默认外壳和内距，业务内容分层                 |
| 弹窗     | Modal / AlertDialog                                                         | 标题、描述、关闭、焦点返回，危险动作明确确认 |
| 反馈     | Toast / Alert / Drawer 通知中心                                             | 一套 Toast 队列；不替代字段错误或持久通知    |
| 数据状态 | Table、ProgressBar、Meter、Spinner、Skeleton、EmptyState                    | 单位、时间和文字摘要齐全                     |

完整 **58 类映射**见 [采纳提案第 4 节](heroui-adoption-proposal.md#4-58-类组件覆盖与处理方式)。Tree、Stepper、图表、上传、应用导航、富文本、音视频与分隔工作区由业务或现有领域引擎负责，不宣传为 HeroUI 已有完整组件。

可见控件统一库外观；保留库输出的隐藏原生表单语义。系统文件选择和权限确认仍由 OS 提供。

## 6. 状态与交互

页面必须覆盖 ready、loading、empty、error、offline（涉及联网时）及成功反馈。设计稿顶部状态切换仅供评审。组件展示 default / focus / disabled / pending / selected / invalid，hover、pressed 用真实操作观察。

提交顺序：按已确认业务校验 → pending 防重复 → 成功后按原流程关闭或刷新 → 失败保留输入并重试。关闭弹窗不隐式取消后台任务；取消必须显式，长期任务可从列表或通知找回。设计稿任务和文案保存在应用层，关闭 / 重开、切页不会丢失，刷新预览会清除。

**订阅新增 / 编辑弹窗：用户已确认沿用现状**，关闭按钮、Escape 或点击遮罩直接关闭并丢弃未保存修改，下次新建为空表单、编辑从已保存数据重新载入，不增加放弃确认。此规则不扩展到文章编辑器或其他业务弹窗；它们须核对各自业务。

Escape 先关闭子浮层再关闭主弹窗，关闭后返回触发器。禁止嵌套 button/anchor 或强转 MouseEvent 模拟旧 API。Voiceover 的导入、后台识别、降噪、克隆、生成、取消、重试与试听必须保留，不新增“人工确认参考文本”前置条件。

播放器保留单音源互斥、加载、错误、播放/暂停和可访问进度。设计稿无真实音频时禁用试听；模拟生成明确标识，不伪造已保存或导出。

## 7. 文案与无障碍

简体中文为主，品牌和模型名保留原文。按钮采用动词；错误交代原因、输入是否保留与下一步。时间使用用户时区，样例固定 2026-10-22、Asia/Shanghai；费用、用量、时长带单位。

必须检查 Tab / Shift+Tab、Space、方向键、Enter、Escape 和焦点返回。表单有可访问名称，图表有文字摘要，任务状态经 live region 或组件语义宣布。文字至少 4.5:1，功能图形和焦点至少 3:1；高对比、reduced-motion、200% 缩放须实测，上游组件不免除业务组合验收。

## 8. 开发、评审和例外

**不确定先确认**：设计师必须核对现有代码和业务契约。无法据此确定的默认值、必填条件、删除 / 恢复、关闭后的草稿处理、任务并发、重试幂等、账户过期和布局变化，整理“当前行为 / 问题证据 / 选项与影响”直接请用户确认，未确认项登记为待决，不得写成已批准规则或带入开发。明确的用户决策可直接执行。

逐页审核与业务状态详见 [交互审核清单](interaction-audit-v2.md)。设计稿中的简化表单和占位详情不代表可删除生产字段或能力；进入生产开发前必须补齐该页全部未覆盖状态并确认待决项。

开始 UI 变更前阅读本规范与相关页面规格。新增通用交互先核实同版本导出与源码，业务组合登记用途、状态、组件映射和键盘行为。主题适配集中维护。

交付必须附受影响页面/组件、变体选择、状态矩阵、明暗截图、1440/1024 与 200% 缩放、键盘/业务结果和未解决项。生产迁移额外通过 `pnpm exec tsc --noEmit -p tsconfig.web.json`、`pnpm exec tsc -b --pretty false`、`pnpm build` 和 Electron 打包运行；根 `tsc --noEmit` 不代表全项目通过。

`pnpm design:check` 验入口、布局源、精确版本和设计稿意外组件外观覆盖；`pnpm design:build` 验真实工作台。CI 执行两项。通过仅证明设计资产合同，不代表生产全部合规或完整 WCAG 通过。

例外写入 [迁移台账](migration.md)：ID、具体路径、场景、理由、负责人、退出里程碑、证据。生产旧样式是待迁移存量，新组件不得扩大例外。改变上游外观须先更新规范边界与例外，不可逐页隐式覆盖。

升级上游须独立评审源码、许可证、精确版本和锁文件、截图差异及高风险交互；同步本规范版本与台账后再采用。
