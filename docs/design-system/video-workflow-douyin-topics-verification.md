# 抖音话题参数纠偏 · 2026-10-26

## 根因

用户发布的“霍去病”作品显示五个 `#标签`，但无法点击。应用正确将标签逐个传给 Catbus `--tag`；Catbus 0.2.1 的 `publishDesc` 只把这些标签拼入描述，`videoItem` 却将 `text_extra`、`challenges` 固定为 `[]`，`hashtag_source` 固定为空。应用原有测试仅检查 CLI 参数和稿件回执，没有校验最终投稿正文的话题结构，因此未发现此限制。

根据 2026-10-26 读取的官方创作者中心静态发布代码，普通新话题也需要 `type: 1`、`hashtag_name`、`hashtag_id: 0`、空 `user_id`，以及完整正文的 `start/end` 和简介的 `caption_start/caption_end`。两套位置均按 JavaScript UTF-16 长度计算；完整正文位置包含已去首尾空白的标题及一个分隔空格。官方编辑器在输入新话题后按确认键、以及自动追加未指定 ID 的话题时使用 ID 0；这类新话题不会被加入只收录非零 ID 的 `challenges`，来源为 `search`。

源页面：[抖音创作者中心](https://creator.douyin.com/creator-micro/content/upload)。相关公开静态代码位于 `douyin-creator-content-new/micro/static/js/async/`：`223.786b7603.js` 的正文派生函数、`3282.34e67726.js` 的话题追加函数、`2320.ab744159.js` 的编辑器确认逻辑。静态代码保存在本机 `/tmp/douyin-official-chunks`，只作为本次证据，不成为项目运行依赖。

## 修复方式

新增 `douyin-topics.ts`，将审核标签规范化、去重，复用简介中已存在的同名话题，生成结构化元数据。只有本次抖音带标签的视频投稿进程启用临时 Node 模块预载；在 Catbus 构造完视频 common、签名提交之前补齐字段。保持原 CLI 上传、会话、签名与回执链路。B 站、账号操作、无标签投稿继续使用既有调用。

此兼容仅面向已固定的 Catbus 0.2.1。启动投稿前核对原视频构造函数标记，实际模块加载时再次核对 SHA-256；运行时核对原正文与简介后才加入元数据。格式不兼容或话题名无效时在上传进程启动前报出明确错误，不静默退回纯文字投稿。临时预载文件使用账号隔离目录和 0600 权限，成功、失败或取消后清理；不改写全局安装的 CLI。没有调整 renderer、控件或页面布局。
