# MG 要求与 AI 修改意见验证

日期：2026-10-24，Asia/Shanghai。

## 根因与修复

1. 分镜提示明确要求无脚本静态关键帧，预览也禁用 CSS 动画。这是审核用画面的既有边界，但粗剪原先没有消费 MG 注释；没有风格模板动效时只使用默认标题入场。
2. 分镜弹窗调用的 `onAiModify` 没有从 props 取出，点击会失败。即使取出，`StageWorkspace.generate` 原先只接两个参数，会丢掉第三个参数中的自然语言意见，并可能继续走模板执行器。
3. 文案修改建议原先只在当前调用中使用。现在文案要求与单镜修改意见以可选 `requirements` 字段存入现有 JSON 修订，编辑文案保留该字段。兼容旧数据，无数据库 schema 迁移。
4. 明确 MG 要求来自简报、文案、已保存要求、自由创作描述或 HTML 动效注释时，首次粗剪、旧默认动效重做和分镜变化后的粗剪先生成全镜动效，再用实际配音时长编译。已有有效自定义动效在仅配音变化时继续复用。
5. 缺少 Agent、上游能力不满足、计划漏镜、目标元素无效、关键帧没有变化，均使任务明确失败并保留旧版本。AI 单镜修改原样返回时拒绝生成新修订。已有“生成修改计划 → 人工确认 → 新粗剪”流程保留。

## 验证

- `pnpm test:video-workflow`：39 项通过，覆盖要求提取、完整上下文、版本复用、缺少 Agent、漏镜、上游错误、意见持久化、重复修改及原样返回保护。
- `pnpm test:video-workflow:ui`：真实 Electron 点击“让 AI 按意见修改此镜”，使用可控 CLI 捕获提示词并断言意见确实进入主进程；结果为待审核修订，未选中分镜不变。继续通过明暗、1440/1024/200%、键盘、预览沙箱和审核回归。
- `WORKFLOW_MG_REQUIREMENTS_SMOKE=1 WORKFLOW_MOTION_REVIEW_SMOKE=1 pnpm test:video-workflow:render`（另配置本地固定 HyperFrames 0.8.181 和 Node 路径）：真实渲染两镜、4 秒视频。每镜包含标题和正文两项动画，工程包含编译后的元素选择器和延迟。对第 3、27 帧只取视频流计算 MD5，确认入场与稳定帧不同。
- 同一真实渲染回归继续验证修改计划持久保存、人工确认、新粗剪 v2、配音复用、正式成片、发布导出和依赖失效；不使用生产项目或改写用户已有媒体。
- `pnpm design:check`、`pnpm design:build` 通过；UI 测试内 `pnpm build` 通过。
- 全项目 `tsc` 仍有既有的 WebView、IPC effect 返回类型、图标声明和编辑器类型错误。本次视频工作流文件无报错，先前 `onAiModify` 未定义错误已消除。不能声称全项目类型检查通过。

## 使用与边界

已有视频文件保持原内容，需重新合成动态粗剪才会得到新版 MG。分镜未变化时可复用已审核配音；分镜修改仍按现有依赖审核流程执行。

HTML 分镜预览仍是静态关键帧，实际动画在粗剪中确认。受限动画支持透明度、位移、缩放、旋转、有限循环和现有镜间转场，不执行模型返回的脚本。结构校验和真实渲染可证明意见已经传入、目标存在且产生动画；自然语言审美与具体表现仍由用户预览审核。
