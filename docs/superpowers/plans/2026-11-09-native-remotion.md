# Native Remotion 实施计划

**Goal:** 将新建 Remotion 粗剪从 HTML 播放适配升级为 Agent 创作原生 React 视频工程，解除页面构图和 WAAPI 枚举对画面的限制。

**Architecture:** 已审核分镜提供事实、风格、素材与叙事意图；原生工程独立编排视觉与镜内镜头。可信入口管理配音、字幕、总时长，创作模块管理画面；源码和素材冻结后供正式渲染与工程导出复用。历史 HTML 工程继续按原入口渲染。自然语言修改仍先生成计划、人工确认后应用；单镜修改限定对应源码模块，其他模块保持不变。

**Tech Stack:** Electron / TypeScript / React 18 / Remotion 4.0.541 / FFmpeg。

## 约束

- 在已有 video-studio-workflow 工作树实现，保留当前未提交修改；不提交、不创建分支。
- 原生模块可使用 React、Remotion 的帧驱动逻辑、SVG、Canvas、CSS 和已检测的浏览器依赖；不预设镜头、对象、动画或布局枚举。
- 生成失败不退回 HTML 动效；旧版可预览，正式成片仅使用已审核冻结源码，不调用 Agent。
- 源码由浏览器渲染，应用负责入口、文件路径、导入依赖和输入指纹检查；不能把静态检查描述为安全沙箱。
- 用户媒体与配音不自动重生成，明确保留 MG 排除设置；不新增布局或改变既有审核入口。

`pnpm test:video-workflow` 验证版本与审核；原生专项测试验证无 iframe 的实际输出、非线性运动、自定义 SVG、局部编辑和冻结复用；`WORKFLOW_REMOTION_PATH=... pnpm test:remotion:render` 保证历史工程仍可输出。设计及 Electron 检查按 spec-v2 执行。
