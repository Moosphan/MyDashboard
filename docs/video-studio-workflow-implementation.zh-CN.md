# 视频创作工作流：实现方案与使用说明

分支：`feature/video_studio_workflow`。沿用现有 React 18、Tailwind 3、Button/Card、Radix 表单/弹窗与配音组件；不引入 HeroUI 迁移。例外已登记在设计迁移台账 `VIDEO-WORKFLOW-001`。

## 1. 产品闭环

| 步骤      | 输入与交付                                           | 人工审核重点                   |
| --------- | ---------------------------------------------------- | ------------------------------ |
| 创作简报  | 想法、观众、核心观点、目标秒数                       | 范围与目标，最长 300 秒        |
| 内容文案  | 本地 Codex / Claude Code，或 Markdown/JSON 导入      | 内容结构、事实与来源           |
| HTML 分镜 | 视觉模板族或 Agent 自由创作，逐镜 HTML 预览          | 信息密度、场景布局和视觉一致性 |
| 口播稿    | 与已审核分镜 ID 和顺序对应的文本                     | 发音、听觉表达和时长           |
| 配音音频  | 现有 Edge / VoxCPM2 / Qwen3-TTS 队列，或逐镜文件导入 | 完整试听、分镜节奏和字幕       |
| 粗剪预览  | 隔离截图 + 配音 + 字幕 → HyperFrames MP4             | 观看整片并确认音画             |
| 最终成片  | 同一个冻结工程按交付质量渲染                         | 最终 MP4 与字幕                |
| 平台发布  | 两平台元数据审核 → 独立发布包 → 手动上传 → 回填链接  | 标题、简介、标签及平台结果     |

同一份 1920×1080、30 fps 横版视频用于 Bilibili 与抖音。生成从不自动审核，也不会自动运行下一步。返回前一步修改会让后续版本进入“需更新”。

## 2. 界面与交互

- 默认进入项目列表，支持创建、继续、归档和恢复。旧封面、音频和演示文稿保留在“素材库”，AI 配音入口保持可用。
- Stepview 展示八个步骤、当前步骤、已通过、待审核、需更新和生成中。允许查看锁定步骤，写入仍由后端审核门禁限制。
- 当前产物与240px审核侧栏并列；1024–1199px审核栏224px，间距16px。1024px及以上步骤八列，较窄四列两行，审核区置于内容之后。
- 分镜按主预览、镜头信息、缩略图、屏幕文字/口播排列。创作设置与单镜编辑使用可取消弹窗；每镜可以独立调整标题、正文、布局、HTML、顺序，也可单镜重绘。
- 模板族是配色/字体/版式语言，不是重复套同一页。首期提供开场、分栏、步骤、对比、引言、总结六种布局。
- Agent 可同时接收描述、公开链接、HTML 文件。公开网页先冻结快照；需要登录、内网或资源无法读取时，改用文件/描述。
- 输入保存在本地草稿中，切步骤、离开页面和重开后可找回。若服务器版本已更新，保留草稿并提示选择载入最新内容，或显式基于最新依赖继续编辑。保存仍使用 CAS。
- 审核弹窗展示具体阶段版本，可填写备注；失败不关闭弹窗。设置与审核弹窗支持 Escape、Tab 和焦点返回。
- 任务进度使用真实阶段文字，不显示推测百分比。显式取消会终止进程；关闭页面不会取消任务，退出或崩溃后不自动恢复执行。
- 口播定稿标题右侧提供“AI 生成口播稿”，再次生成显示“AI 重新生成口播稿”。根据已审核的简报、内容文案与 HTML 分镜生成整片逐镜口播，原样保持分镜 ID、数量与顺序；可给出读音/停顿提示。右侧选择 Codex / Claude Code，也可导出任务后人工导入。未保存修改需先保存或放弃，执行中暂停口播编辑；结果停在待审核，不自动配音。

## 3. 持久化与一致性

简报新增可选受众、参考资料，逐镜口播新增可选读音提示，均随阶段 JSON 持久化，兼容旧数据。读音提示供人工校对，不直接混入朗读文本。版本历史可载入为本地新草稿，保存后新增版本并重新审核。

SQLite migration 34 新增项目、阶段版本、幂等请求、任务、文件、发布记录六组表。配音依赖 migration 33。阶段内容版本只追加，保存创建新版本；审核状态和审核时间绑定具体版本。

`src/shared/video-workflow.ts` 是 IPC、编辑器和主进程共同使用的阶段契约。主进程 `VideoWorkflowService` 负责文件校验、执行与发布；`VideoWorkflowRepository` 以事务实现以下规则：

1. 保存、审核和启动任务均校验项目版本；旧页面不能覆盖新结果。
2. 阶段依赖指纹包含所有前置阶段的已审核版本 ID。
3. 修改某阶段，将所有后续版本标为失效；旧发布包和发布记录保留。
4. 请求 ID 幂等且绑定操作/任务输入；同 ID 不可用于不同内容。
5. 同一项目同时只运行一个工作流任务。任务结果回写再次检查项目版本和任务状态，取消/失效任务不能注册迟到结果。
6. 启动时将未完成任务标为中断，用户可显式重新生成。

工作流媒体存于 `userData/media/video-workflow/<project UUID>/`，数据库登记相对路径、SHA-256、MIME 和文件大小。导入复制原文件，生成音频也复制到项目空间，因此源文件改动或素材库回收不会破坏已冻结产物。审核、生成和导出前验证依赖文件完整性。归档保留历史与文件；首期不自动清理历史产物。

## 4. CLI 与人工协作

执行环境可配置 Node.js、Codex、Claude Code、HyperFrames、FFmpeg、FFprobe 的绝对路径。配置仅保存在本机，不引入新的模型 API Key。先使用各 CLI 自身流程完成登录。

- Codex：非交互 `exec`，只读 sandbox，临时任务目录，stdin 输入完整上下文，读取最后一条回复。
- 内容生成使用本次进程的配置覆盖关闭 Codex 插件、Apps、子代理和已配置的 MCP 服务，不修改用户配置、模型或登录信息。仍允许读取用户指定的本地绘图技能，预览和画幅、动效检查由宿主完成，避免在分镜任务中反复启动浏览器。
- 整组 Agent 分镜创作最多 30 分钟，单镜、文案和口播创作最多 15 分钟；等待期间显示已用分钟数。超时不会保存不完整 JSON，原版本保留，取消仍终止整个进程组。CLI 配置读取另有 15 秒上限。
- 2026-10-27 现场验证：张良项目原任务在 15 分钟被终止，末尾仍在读取绘图技能并尝试预览工具。隔离后真实重生成耗时约 5 分 22 秒，10 镜以 1080×1920 保存为待审核 v2；稳定 ID、逐元素动效目标和 Chromium 画幅校验通过，原 v1 保留。工作流回归测试 73/73 通过，构建通过；全项目类型检查仍有既存 82 条诊断，本次变更文件无新增诊断。
- Claude Code：`--print --output-format json --tools "" --no-session-persistence`，解析 JSON 输出。
- 两者仅生成阶段 JSON；格式或语义校验失败会停在任务错误，不自动写入草稿或审批。
- 导出任务得到 `task.md` 和已审核输入快照；可在外部 CLI/编辑器完成工作，随后导入 `result.json`。导入内容始终作为待审核的新版本。
- 文案也接受 `.md/.txt`；分镜接受完整 `.json` 或单页 `.html`；逐镜口播使用 JSON，以稳定 ID 保持对应。

示例分镜：

```json
{
  "mode": "agent",
  "template": "editorial",
  "scenes": [
    { "id": "scene-1", "title": "提出问题", "body": "一个核心问题", "layout": "title" },
    {
      "id": "scene-2",
      "title": "解释原理",
      "body": "原因一\n原因二",
      "layout": "split",
      "html": "<style>body{background:#f4f1e8}</style><h1>独立画面</h1>"
    }
  ]
}
```

口播结果：`{"scenes":[{"id":"scene-1","text":"第一镜口播"},{"id":"scene-2","text":"第二镜口播"}]}`。

## 5. 音频与 HyperFrames

长口播按语义拆到每段不超过 300 Unicode 字符，使用现有配音队列，不新增本地模型并发通道。本地克隆绑定已保存音色版本。每段通过 FFprobe 校验，统一为 48 kHz 单声道 WAV，再合并完整配音，实际时长超过 300 秒会拒绝。外部配音按文件名自然排序导入，数量必须与分镜数量一致。

首期固定 HyperFrames **0.8.181**，使用外部 Node.js 22+；不在产品内静默安装或升级。既可配置可执行入口，也可配置安装目录的 `bin/hyperframes.mjs`。FFmpeg/FFprobe 和配音本地模型需由用户准备；运行检测会给出具体缺失项。

若粗剪在 0 秒内报“请先配置可执行文件路径”，先检查右上角执行环境的 HyperFrames 路径；安装 skill 不等于应用已配置 CLI。渲染启动前会明确提示缺少哪项环境及配置入口，`.mjs` 方式还需要 Node.js 路径。本机已配置现有 0.8.181 入口与 Node 24，不需要重新生成或审核已有音频。

HTML 分镜审核仍为无脚本静态关键帧。新粗剪保留安全 DOM/CSS，在禁止网络、Node、preload 和源脚本的独立 session 中整理内容并作用域隔离，元素 ID、SVG 引用和选择器按镜头命名空间重写。只将结构化、有限时长的位移/缩放/旋转/透明度关键帧编译为应用自己的 WAAPI 脚本，由 HyperFrames adapter 按时间 seek；不执行输入 HTML 的脚本或 CSS 动画。PNG 继续用于封面；旧截图工程仍可按原冻结内容渲染。

粗剪使用 `looks` 质量，人工审核后最终成片使用 `delivery`；两次使用相同工程文件指纹，不重新调用 Agent。每次渲染前执行 `hyperframes check --json --samples 9`，必须实际进入浏览器并产生非零样本。输出还需满足音轨、1920×1080 和实测时长校验。

粗剪下方“提出修改”记录当前镜/整片、真实播放时间和意见。Agent 只返回声明式动效计划，先校验选择器实际存在、镜头身份、时长及允许属性，再保存为任务结果；不改审核状态。用户确认计划后创建新版粗剪，只使成片/发布依赖失效。计划绑定项目 revision，过期、跨项目、失败或未完成计划不能应用。新版本保留旧版，支持历史预览；新工程记录来源分镜、口播和音频版本，历史定位使用对应来源。

正片审核通过后可保存风格模板（数据库迁移 36），冻结名称、描述、封面、原始多镜样式和已有动效。分镜设置中的“我的模板”由本地 Agent 结合新文案生成不同版式，样本作为风格参考，不复制旧文案/口播。用于模型的样本均匀取最多六镜并省略内联二进制素材，完整样本保留在模板中。模板动效重新适配当前元素与实测音频时长；当前不提供完整参数化模板编辑器。

“导出可编辑工程”创建源码副本，包含 index.html、本地音频、封面、工程元数据和说明。可在导出目录用 HyperFrames 0.8.181 执行 `preview --background`，打开命令打印的 `http://localhost:<port>/#project/<name>` Studio 链接。该链接需要本地服务运行；Studio 编辑的是工程，不是 MP4。可在 Studio 或 CLI 重新导出，当前不自动回导到 MyDashboard，不能绕过工作流审核。暂无内置时间轴拖拽、Remotion、BGM 混音与自动素材检索。字幕仍需人工试听校对。

## 6. 安全与发布

所有新 IPC 仅接受应用主窗口的 mainFrame。HTML 预览在不带 `allow-scripts/allow-same-origin` 的 sandbox iframe 中显示，并额外应用禁止脚本、联网、嵌套框架和表单的 CSP。网页参考限制公开 IPv4、标准 HTTP(S) 端口与三次跳转，每跳重新解析并固定目标地址，限制响应时间和大小。

受管媒体通过独立 `video-workflow://` 协议读取，只开放已登记的音频、视频和图片，不开放 HTML 或任意磁盘路径。子进程不用 shell 拼接命令，提示词通过 stdin 传入，支持超时、输出上限和取消进程组。

发布包包含 `video.mp4`、`cover.png`、`subtitles.srt`、`metadata.json`、`manifest.json` 和人工上传说明。每次导出创建新记录，绑定已审核的发布版本和视频 SHA-256。两个平台独立导出与回填，仅接受对应平台 HTTPS 域名；回填是用户人工记录，不表示系统已核验平台投稿成功。

工作流文件包含在现有媒体备份中。恢复备份前先停止工作流和配音任务，避免向旧数据库继续回写。

## 7. 验证与运行

### 分段配音在重启后提示“请检测本地环境”

本地模型就绪状态只保存在内存，重启后会恢复为未检测。原工作流直接调用配音任务创建接口，未走配音工具的手动检测入口，因此本机模型即使已安装，也会在生成前立即失败。

分段配音现在在本地引擎未就绪，或启用降噪但降噪未就绪时，先自动检测配音与降噪环境，并将该阶段显示在执行日志中；检测完成后再创建逐镜配音任务。真实缺失/不兼容仍会显示检测原因，不绕过校验。在线预设和外部音频导入不触发本地模型检测，取消后不再继续生成。

回归命令：`pnpm test:video-workflow`、`pnpm test:voiceover`。真实冷启动验证：`ELECTRON_RUN_AS_NODE=1 pnpm exec electron --import tsx scripts/smoke-workflow-voice.ts '<现有用户数据目录>'`，只读原音色信息与配置，在独立临时目录复制参考音频并生成两镜测试口播；不修改原项目、音色或任务。

2026-10-23 实测：冷启动回归先在旧代码复现“请检测本地环境”，修复后工作流 20/20、配音 24/24 通过。真实 VoxCPM2（20 步、CFG 2、降噪开启）两镜生成、合并 WAV 与字幕校验通过，合计 5.760333 秒，结果停在待审核。隔离产物目录 `/var/folders/tp/lp03pbbn6wb275zsvn3lfrq00000gn/T/workflow-local-voice-SWCILB`，日志 `/tmp/workflow-audio-real.log`。构建、受影响文件 ESLint / Prettier 通过；完整类型检查与前一轮归一结果均为 65 项、无新增，本轮没有 UI 布局改动。

### macOS 拦截 Codex CLI

若系统提示 `codex` 有害或已损坏，取消运行该文件，不移除隔离属性或关闭系统保护。在“执行环境”选择另一个来自可信安装且完整性检查通过的 CLI，或从官方来源重新安装。Codex 桌面应用的独立 CLI 可位于 `/Applications/Codex.app/Contents/Resources/codex-cli/CodexCLI.app/Contents/MacOS/codex`；路径随安装版本而定，先检查再配置。

工作流现在保留子进程终止信号、执行路径与 stderr；被信号终止时不再显示无意义的“退出码 null”。SIGKILL 本身不能证明由系统安全机制拦截，也可能来自其他进程或系统资源回收，应结合系统提示判断。

2026-10-23现场修复：应用默认路径命中了 npm 安装的 Codex；用户截图出现 macOS 安全拦截，两个任务均以“退出码 null”失败。本机已将工作流的 `codexPath` 显式配置为签名完整性验证通过的 Codex 桌面应用内 CLI，并实际验证版本与模型调用；未执行被拦截的文件，也未改动系统安全策略。

修复验证：新增 SIGKILL / SIGTERM 回归测试先失败后通过，工作流共18项通过；真实 Agent 分镜测试在隔离数据库中生成两镜 HTML，任务成功并停在待人工审核，未改写用户项目。证据为 `/tmp/video-agent-tests.log`、`/tmp/video-agent-real.log` 与 `/tmp/video-agent-stage.log`。应用已清理旧实例后重新启动到 `ready-to-show`。

```bash
pnpm test:voiceover
pnpm test:video-workflow
pnpm test:video-workflow:ui
WORKFLOW_HYPERFRAMES_PATH=/absolute/path/hyperframes/bin/hyperframes.mjs \
WORKFLOW_NODE_PATH=/absolute/path/node pnpm test:video-workflow:render
```

合成 smoke 使用明确标注的合成音频测试两镜完整链路，不调用付费模型或上传平台；UI 测试使用临时 profile 和实际 Electron/IPC。设置 `WORKFLOW_SEED_DIR` 为合成 smoke 的产物目录可额外验证协议范围读取。

独立 profile 运行：`MYDASHBOARD_USER_DATA=/absolute/path/test-profile pnpm dev`。未设置该变量时保持原有用户数据位置。生产主目录与本功能隔离工作目录互不替换。

最终验证证据与尚未覆盖项记录于分支交付报告；CLI 适配器使用可执行测试替身验证参数和结果解析，真实模型输出质量与登录状态仍取决于用户本机配置。

## 8. 本次交付验证（2026-10-23）

### 配音增量修订

- Edge TTS 的旧依赖 2.0.5 使用 `speech.platform.bing.com` 合成地址，真实请求返回 403。固定升级至 `msedge-tts@2.1.0`，采用上游修复的 `api.msedgeservices.com/tts/cognitiveservices/websocket/v1` 与 `Ocp-Apim-Subscription-Key`；不修改 node_modules 或私有 API。403 地址问题与在线服务 429 限流须区分，429 显示稍后重试，不静默切换引擎。
- 数据库迁移 35 增加任务 `audio_progress`，保存成功归一化并登记到受管目录的音轨及真实总段数；每段持久化后发送原有 `workflow:updated`。关闭页面、失败、取消或退出中断不会删除成功片段。正式音频版本仍仅在全段完成、合并及字幕校验后建立，并等待人工审核。
- UI 优先展示最新且输入版本仍有效的任务片段；重做时区分此前完整产物，新任务不混用旧片段，上游修改隐藏过期片段。播放器使用文件 ID 稳定标识，后续片段追加不会打断正在试听的音轨。以真实媒体事件驱动标题/按钮高亮、加载、暂停、结束与单音源互斥。
- 可复跑 `ELECTRON_RUN_AS_NODE=1 pnpm exec electron --import tsx scripts/smoke-workflow-edge.ts`，在隔离目录验证真实中文 Edge、逐段通知、完整 WAV/SRT 与审核门禁；该测试需要网络，服务端限流会如实失败。完整验证及边界见 [配音增量验证](design-system/video-workflow-audio-progress-verification.md)。
