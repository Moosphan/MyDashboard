# 分段配音版本历史与 Qwen3 音色一致性验证

日期：2026-10-24

## 版本历史

- 音频版本复用 `video_workflow_revisions`，每个版本保留阶段版本号、创建时间、审核状态和完整音频 payload。
- 音频面板可选择当前版本或历史版本，历史版本显示 `vN · YYYY/MM/DD HH:mm:ss`，选择后可直接试听所有片段和完整音频。
- 只有参考口播依赖仍匹配、受管文件校验通过的历史版本可以“切换为当前版本”；切换会创建新的待审核音频版本，粗剪及后续产物失效。
- 过期、缺失文件、运行中任务和跨项目版本均被拒绝；恢复失败不改变当前音频。

## Qwen3 第九段异常定位

Qwen3-TTS Base 的克隆路径需要同时传入冻结的 `ref_audio` 和准确的 `ref_text`，不能传 preset speaker。当前适配器保持这条路径，worker 也会在每个任务开始前按请求种子初始化 MLX 随机状态。

原工作流把所有片段和单段重生成都使用同一个默认种子 `42`。因此某一段在该采样状态下出现音色漂移时，点击“重新生成此段配音”仍会得到同一个异常结果。问题发生在采样状态复用，不是播放器把第九段替换成其他文件。

现在保留工作流的基础种子，但按片段序号和文本稳定派生片段种子；单段重生成额外加入新任务 ID 作为盐值。完整生成的同一片段可复现，新任务不会被固定 `42` 锁死。生成元数据仍记录最终请求选项、音色档案版本和参考 SHA-256，便于核对实际输入。

## 验证范围

- `pnpm test:video-workflow`：覆盖片段种子派生、单段重生成、历史版本恢复和失败保留旧版本。
- `pnpm test:voice-runtime`：覆盖 Qwen3 Base 的 `ref_audio` / `ref_text` 传递，确认不传 preset speaker。
- `pnpm exec electron scripts/test-workflow-audio-controls.cjs`：覆盖历史版本时间/版本选择、恢复、原生播放器、单段菜单、失败保留、主题、1440/1024/200% 缩放。

当前环境未安装用户本机 Qwen3 模型，无法在这里对第九段实际女声相似度做试听；安装模型后应优先重新生成第九段并核对生成目录中的 `generation.json`：`profileRevision`、`referenceSha256`、`options.seed` 和 `text` 必须对应当前音色版本与第九段文案。
